Technical audit and remediation

A review of security, scalability, concurrency, usability, database design, architecture, code quality and the AI layer. Each finding keeps its original problem and fix, and now shows what was done about it and what is still open.

Verdict

7.3 / 10
Ready for a supervised pilot; not yet for an open public launch.

Was 4.5 before the fixes. The webhook now only stores and answers, and a worker processes a durable queue. Tenant isolation, role limits, lockout and instant session revocation are covered by 33 passing automated tests. Tools, memory and prompts are hardened, and tenants and admins get usage and health monitoring. Still open: MFA (left out as requested), a load test, a live TencentDB check, the controller/service refactor and a few compliance documents. Scores are my estimates, not measurements.

Scorecard

Production readiness after the fixes, 10 is best

What is already solid

  • Every query uses prepared statements; the few dynamic parts are whitelisted or cast to integers.
  • Every tenant query carries tenant_id from the session, never from user input.
  • Webhooks verify Meta's HMAC with a constant-time compare and reject channels that have no app secret.
  • Customer-bound tool parameters work: a lookup with another customer's phone returned 404 in testing, even when the AI supplied that phone.
  • Tokens and API keys are encrypted with AES-256-GCM and never shown again.
  • Output is escaped on the server and written with textContent in the browser.
  • CSRF tokens on all forms and API calls, session id regenerated at login, passwords hashed with password_hash.
  • The agent loop has a step cap, a handoff tool, a fallback message and a graceful path when Gemini is down.

Findings and fixes

Still open

  1. MFA for super admins and owners. Excluded at your request.
  2. Production setup: HTTPS, APP_ENV=production, a dedicated least-privilege database user with a password, the queue worker under a supervisor. The posture checklist on Platform → Operations tracks these.
  3. Live checks I could not do: Meta delivery including voice notes and images, and a running TencentDB Agent Memory service (php cli/verify_tencent.php lists its real tool names).
  4. Load and soak test to find real capacity numbers, and a first PHPStan run.
  5. Controller, service and repository refactor (F32), the largest remaining code-quality item.
  6. Documents: privacy notice and data-processing addendum; optional KMS, per-tenant keys and table partitioning.
  7. Reply speed: each Gemini call took between 0.7 s and 8 s in testing, so replies with tool calls took 6 to 17 s. Try a faster model or a lower GEMINI_THINKING level and compare on your own traffic.

Target architecture

The change that matters most is separating "receive" from "reply". Everything else in the list hangs off that split.

flowchart LR
  Meta[Meta webhooks] --> Edge[Webhook endpoint: verify, store, answer 200]
  Edge --> Q[(Event queue)]
  Q --> W[Worker pool with per-conversation lock]
  W --> LLM[LLM gateway: limits, breaker, budgets]
  LLM --> G[Gemini]
  W --> TG[Tool gateway: validate, cache, SSRF-safe]
  TG --> ERP[Tenant ERP / CRM]
  W --> M[Memory: MySQL or TencentDB]
  W --> Out[Outbound sender: retry and status]
  Out --> Meta
  W --> DB[(MySQL)]
  UI[Dashboard and inbox] --> DB

Scope and limits of this review

Original review: a read-through of all application files plus manual smoke tests. After the fixes: 33 automated tests (unit, tenant-isolation attacks, role limits, webhooks, lockout, session revocation, invite links), a live Gemini run in Sinhala and English with tool calls, a signed webhook through the queue worker, and a check of all 24 pages and the blocked paths under Apache.

Still not done: penetration testing, load testing, live Meta delivery (including voice notes and images) and a running TencentDB Agent Memory service. Findings about those areas come from reading the code and the vendors' documented behaviour. F07 and F37 depend on current Gemini guidance and should be confirmed against Google's docs and a real run. The scores are my judgement, not measurements.
